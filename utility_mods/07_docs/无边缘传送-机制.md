# 地图边缘区域传送的触发与关闭（GU v1.4.0）

结论先行：**每帧检测"玩家是否踩进区域移动点"的函数是 `0x50005C`**
（main.c 的 `sub_6050005C`，可叫 `sStage::checkAreaMove`）。
把它短路成 `return 0`，边缘传送就不会发生；任务开始/返回营地等
其它换区路径不受影响。

## 1. 调用链

```
任务场景任务 sub_6069F9FC(task)           每帧，main.c:1447644
  └─ sub_6050005C(sStage)                   0x50005C，main.c:1156730
       ├─ sub_60276278(sPlayer)             取本地玩家
       ├─ sub_603A5ED0(sQuest, 5, 1)        任务状态门控
       ├─ sub_604FC6A8/6B4(areaData, i)     取区域移动点
       └─ sub_60807368(&shape, player+0x40) 玩家位置是否在触发体内
  └─ 若 sStage+420 & 2：任务切到过渡状态（sub_6069FB68）
```

`sub_6050005C` 只有一个调用者（`sub_6069F9FC`），且调用方不检查返回值。

## 2. 触发点数据

- 当前区域号：`player + 4180`（u8）。
- 区域数据表：`sStage + 904 + 4 * areaNo`（sStage = `dword_618977A0`）。
- 每个区域一个数组，元素 0x30 字节，字段与 DTI 的 `AreaMoveData` 对得上：
  - `+0x10/+0x14/+0x18`：中心 x/y/z（float）
  - `+0x20` 附近：区域/出现点字节（代码里读 `+32`、`+33`）
  - `+0x24`：高度（float）
  - `+0x28`：半径（float）
- 命中后：
  - `area+74 = 下一区域号`（area = `dword_6188CA48`）
  - `area+81 = 出现点序号`
  - **`sStage+420 |= 2`** ← 这就是"请求区域移动"的位。

`sStage+420` 的已知取值：`1` = 空闲；`|= 6`（bit1+bit2）= 任务开始/返回营地类出现；
`|= 0xE` = 任务失败/返回；`|= 2`（只有本函数）= 走到边缘。

## 3. 为什么"任务完成等待结算"时不传送

`sub_6050005C` 开头：

```c
if ( !sub_603A5ED0(dword_6188AD90, 5, 1)      // sQuest 不在特定阶段
  && *(unsigned __int8 *)(dword_6188AD90 + 85) <= 0xC )   // sQuest+85 <= 12
```

`sub_603A5ED0(sQuest, 5, 1)` 对 sQuest 阶段 `+80` ∈ {4,5,6,7,9} 返回 true。
任务完成进入结算流程时，`sub_606A13E0` 会调用 `sub_603A24A0(sQuest, 9)` 把
`+80` 置 9；于是这个 if 直接不成立，函数返回 0，边缘触发点根本不检测。
玩家仍能走，但走到边缘不会再换区——与实测现象一致。

## 4. 只拦普通走位，保留四种换图

玩家动作号：`player+0x250A`（u16，act_no），动作类型 `player+0x2506`。

| 方式 | 放行条件 | 依据 |
| --- | --- | --- |
| 蹲下 / 蹲走 | 站定：`act_no = 23 / 24 / 25` 等；轻推：`act_type = 2 且 act_no = 7`；满推变 `2/6` 时保持"蹲模式"直到停下 | **实测**：蹲走轻推是 `2/7`；满推变 `2/6`（和普通跑同号），用蹲模式区分 |
| 攀爬 | `act_no = 810 / 880 / 1240` | 猎人动作表：上爬 / 下爬 / 攀爬跳跃；**实测**成功；插件里**固定开启** |
| 跳下 | `act_type = 4`（实测 4/0、4/1） | **实测**：放行后区域从 2 切到 8；插件里**固定开启** |
| 切道具 | 长按 L 达到 `item_hold_frames` 帧；点按 L 由 `item_by_tap` 控制；ZL 相关默认全关 | 实测切道具不改 act（恒 1/0），只能按输入判定 |

实测结论（2026-10-31，Eden）：普通走/跑（`1/0`、`1/7`、`2/x`）仍被拦；
蹲下、攀爬、跳下、长按 L/ZL 都能正常换图；点按默认不放行。
攀爬、跳下在插件里硬编码开启，不出现在 ini。

插件的 hook 只在命中以上条件时 `original!(stage)`，否则返回 0。
`log_act = true` 时会把动作变化写进 `forge-loader.log`（排障用）。

## 5. 关闭方法

- **插件（推荐）**：`01_plugins/no_area_move`，hook `0x50005C` 返回 0。
  带函数头校验（`0xE92D4FF0`），版本不符自动跳过。
- **原理等价**：任何让 `sStage+420` 不置 bit2 的做法都行；直接改 `+420` 的值
  也可以，但会和任务开始/返回营地的 `|=6` 抢写，不如 hook 干净。

## 6. 注意

- 只拦"走到边缘"；任务开始/结束、菜单返回营地照常。
- 拦截后玩家可能继续走进原本的换区通道/墙边，游戏不会再自动传送，
  也不会把玩家拉回来。
- 偏移按 GU v1.4.0（`0100770008DD8000`）写死。
